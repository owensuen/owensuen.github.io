test_preview_zoom.py

测试项描述

预检查项

支持 android.control.zoomRatioRange 的设备参与测试。

测试内容与目标

Android 16+ 版本描述：

测试每个预览帧的缩放比例是否与从超广角镜头到广角镜头的相应捕获元数据匹配。

该测试会在变焦范围内拍摄预览帧，并查找最接近画面中心的 ArUco 标记。 随后测试会检查中心标记的位置是否随每次捕获发生预期的变化。 中心标记的中心到画面中心的距离可能会以与缩放比例成恒定速率变化（直至发生物理镜头切换），或者在物理镜头切换后单调地趋近于同一标记的位置。

通过条件： 所选 ArUco 标记的相对尺寸与所有预览帧对应的捕获结果所报告的缩放比例相符。 所选标记与画面中心的相对距离与所有预览帧对应的捕获结果所报告的缩放比例一致。

test_preview_zoom 图像，显示与中心最接近的所选标记：

参考图像

测试的 API：

  • android.hardware.camera2.CameraCharacteristics#CONTROL_ZOOM_RATIO_RANGE

  • android.hardware.camera2.CameraCharacteristics#LENS_INFO_AVAILABLE_FOCAL_LENGTHS

  • android.hardware.camera2.CaptureRequest#CONTROL_ZOOM_RATIO

  • android.hardware.camera2.CaptureResult#LENS_FOCAL_LENGTH

Android 15 版本描述：

测试每个预览帧的缩放比例是否与相应的拍摄元数据相符。 该测试会在变焦范围内拍摄预览帧，并查找与中心最接近的圆圈的轮廓。 随后，该测试会检查所选圆圈是否变大，以及圆圈的中心是否会随着相机拉近而远离图像中心。

通过条件： 对于所有预览帧的相应拍摄结果的报告缩放比例，所选圆圈的相对大小是准确的。 对于系统针对所有预览帧的相应拍摄结果报告的缩放比例，所选圆圈与图像中心的相对距离是准确的。

测试的 API：

异常描述

 
ERROR Max zoom ratio 4.6735 in capture results not close to 10.00 and z_max-step = 9.82 by 0.02 tolerance.

异常原因

后摄 android.scaler.availableMaxDigitalZoom 元数据配置 10，实际仅支持 4。

解决方案

在 custom/mt6789/hal/imgsensor_metadata/sc820cs_mipi_raw/config_static_metadata_project.h 中配置:

CONFIG_METADATA_BEGIN(MTK_SCALER_AVAILABLE_MAX_DIGITAL_ZOOM)
    CONFIG_ENTRY_VALUE(4, MFLOAT)
CONFIG_METADATA_END()

项目

X1201

解决者

zhangyue

备注

X1102M1201-1005 孙海鑫 记录于 2025.06.23

异常描述

详见分析过程。

异常原因

测试项选择到不受支持的异常视频编码尺寸（1920x1920）进行预览和视频录制，硬件编码异常出现内存泄露导致 CTSV 进程被 Kill。

解决方案

修改 metadata 中 1920x1920 尺寸的 frameduration 使该尺寸不可用于预览:

vendor/transsion/itd/vendor_vnd/imgsensor_metadata/metadata_scaler_tablet/transsion_5M_ext_scaler.h

CONFIG_METADATA_BEGIN(MTK_SCALER_AVAILABLE_STREAM_CONFIGURATIONS_WITH_DURATION)
 CONFIG_ENTRY_VALUE(HAL_PIXEL_FORMAT_BLOB, MINT64)
 CONFIG_ENTRY_VALUE(1920, MINT64)
 CONFIG_ENTRY_VALUE(1920, MINT64) // width height
 CONFIG_ENTRY_VALUE(MTK_SCALER_AVAILABLE_STREAM_CONFIGURATIONS_OUTPUT, MINT64)// output
 CONFIG_ENTRY_VALUE(100000000, MINT64) // frame duration (原为 33333333)
 CONFIG_ENTRY_VALUE(33333333, MINT64) // stall duration

 CONFIG_ENTRY_VALUE(HAL_PIXEL_FORMAT_BLOB, MINT64)
 CONFIG_ENTRY_VALUE(1920, MINT64)
 CONFIG_ENTRY_VALUE(1920, MINT64) // width height
 CONFIG_ENTRY_VALUE(MTK_SCALER_AVAILABLE_STREAM_CONFIGURATIONS_OUTPUT, MINT64)// output
 CONFIG_ENTRY_VALUE(100000000, MINT64) // frame duration (原为 33333333)
 CONFIG_ENTRY_VALUE(0, MINT64) // stall duration
CONFIG_METADATA_END()

需要 ExtendedCameraCharacteristicsTest#testAvailableStreamConfigs 要求 YUV 尺寸所有包含 JPEG 尺寸，所以不能去除 1920x1920 的 YUV 配流尺寸。

更多信息

分析过程：

  1. 开始录像后大量 lowmemorykiller，并且最终 kill 了 CTSV:

    lowmemorykiller: Kill `com.android.cts.verifier' (15906), uid 10206, oom_score_adj 200 to free 26892kB rss, ...

  2. Codec 异常占用内存，dump memory 发现 codec 进程占用 1.7GB 内存，严重怀疑 codec 进程存在内存泄漏:

    Total RSS by process: 1,773,088K: android.hardware.media.c2@1.2-mediatek (pid 912)

  3. 分析日志中的 Codec 异常日志:

    C2MtkConvert: [0xEEC83320] Dst buffer change: width 1920, height 1440, format 1
C2MtkConvert: [0xEEC83320] Src buffer change: width 1920, height 1920, format 1
C2MtkConvert: [0xEEC83320] updateConfig: Src(format 1(HAL_PIXEL_FORMAT_RGBA_8888), size(1920,1920), crop(1920,1920), (secure 0), (doFlush 1)), Dst(format 1(HAL_PIXEL_FORMAT_RGBA_8888), size(1920,1440), crop(1920,1920), (secure 0), (doFlush 0))

  4. 跟踪 C2Mtk 源码，排查 1920x1440 这个异常的 Dst buffer size，排查到了 C2MtkVenc::initEncoder 设置 C2_PARAMKEY_PICTURE_SIZE，其中:

    std::shared_ptr<C2StreamPictureSizeInfo::output> getAlignedSize_l() {
    auto alignedSize = std::make_shared<C2StreamPictureSizeInfo::output>();
    alignedSize->width = ROUND_N(mSize->width,std::max(mSupported->step.first, mMinWidthAlignment));
    alignedSize->height = ROUND_N(mSize->height, mSupported->step.second);
    return alignedSize;
}

  5. 当前平台 HW encoder Spec: 2560x1440@30fps，所以理论上宽不能超过2560，高不能超过1440。1920x1920，1920 超过了1440，会被截断为1440。

  6. ITS、CTSV-apk、日志分析:

    Resolutions supported by preview and MediaRecorder: [..., `2560x1440', `1920x1920', `2560x1536', `2560x1920']

    2560x1536、2560x1920 没有被过滤掉是因为硬件编码 prepare/config 失败，但是软件编码 prepare/config 成功:

    E C2MtkVenc: BAD VALUE: Resolution not supported, width 2560, height 1920
E MediaCodec: configure failed with err 0xffffffea, resetting...

    1920x1920 没有被过滤掉则是因为硬件编码 prepare/config 成功了，这是因为 mtk_platform_codecs_config.xml 中 c2.mtk.avc.encoder encoder 的 canSwapWidthHeight 配置为 true，所以只对配置尺寸的面积做了限制判定。但是 MT6789 平台严格检查宽、高不能超过各自的限制最大值。

  7. Codec canSwapWidthHeight 方案验证：

    修改 c2.mtk.avc.encoder encoder 的 canSwapWidthHeight 配置为 false 后，测试项选择 1920x1920 的软件编码并 PASS。

    但导致系统相机视频 HDR 录像配流 1080x1920 MediaCodec config 失败，故回退； 改用”修改 metadata 中 1920x1920 尺寸的 frameduration 使该尺寸不可用于预览”方案。

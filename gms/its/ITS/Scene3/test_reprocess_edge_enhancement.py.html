test_reprocess_edge_enhancement.py

测试项描述

预检查项

不支持 MANUAL_SENSOR 或 POST_PROCESS 的设备不参与测试。

不支持逐帧控制 (PER_FRAME_CONTROL) 的设备不参与测试。

不支持 EDGE_MODE 的设备不参与测试。

不支持 YUV REPROC 且不支持 PRIVATE REPROC 的设备不参与测试。

测试内容与目标

测试支持的边缘增强重处理方法是否正常工作。

通过给定重处理边缘模式处理捕获请求，并与禁用重处理边缘模式的捕获结果进行比较。

测试要求支持 REPROC 的设备必须支持 EDGE_MODE_ZSL 模式。

通过条件：

  • 不同边缘模式的锐度正确无误。

  • HQ（模式 2）比 OFF（模式 0）更清晰，并且不同模式之间的优化程度类似。

[孙海鑫 记录于 2025.11.25]

历史问题

项目

备注

二轮 [1/3] 368718 孙海鑫 记录于 2025.11.21

异常描述

 
DEBUG Calculated FoV: 118.28
DEBUG Camera type: ultrawide
DEBUG Chart distance: 22.00cm
DEBUG Chart height: 9.50cm
DEBUG Focal length: 2.39mm
DEBUG Pixel pitch: 10.00um

DEBUG Chart/image scale factor = 14.96
DEBUG scale start: 9.724, stop: 20.197, step: 0.374
AssertionError: Unable to find chart in scene!
Check camera distance and self-reported pixel pitch, focal length and hyperfocal distance.

异常原因

DUT 与测试图卡平板距离调远（大于30cm）可 PASS，但这不符合标准（22.00cm）。

第一轮挂测修改 FOV 改错，导致计算出来的 FOV 过大：118.28 度，被识别为超广角镜头。

因为 MTK_SENSOR_INFO_PIXEL_ARRAY_SIZE 为 (8000, 6000)，应为 (4000, 3000)。

解决方案

针对 SENSOR_DRVNAME_IMX855_MIPI_RAW 控制修改 MTK_SENSOR_INFO_PIXEL_ARRAY_SIZE； metadata 配置 MTK_LENS_INFO_AVAILABLE_FOCAL_LENGTHS。

修复后正常识别图卡，但测试项仍 FAIL。

备注

二轮 [3/3] 368718 孙海鑫 记录于 2025.11.21

异常描述

 
AssertionError: HQ/OFF_0: 1.0053, HQ/OFF_reg: 1.2846, RTOL: 0.15

异常原因

普通拍照和 reproc 拍照的 EE 曲线变化不一致。

解决方案

paramctrl_per_frame.cpp prepareHw_PerFrame_EE 中添加日志分析发现：reproc 拍照的二阶段没有走 EE:

fgRPGEnable(0), level 0 mode 3 not do EE
bDisable(0), rSeee.isCCTEEEnable() 1 ee_en 268435456, eIspProfile 2
fgRPGEnable(0), level 0 mode 1 not do EE
bDisable(0), rSeee.isCCTEEEnable() 1 ee_en 0, eIspProfile 54

每次 reproc 拍照分为两阶段：

  1. profile:2 (Capture) edge.mode:3；

  2. profile:54 (YUV_Reprocess) edge.mode:x。

其中一阶段 edge.mode:3 不走 EE 是合理的，但是二阶段是应该执行 EE 的，ee_en 0 存在异常， 分析发现是另一个问题解决过程中禁用了 YUV_Reprocess 的 ISP 处理。

修复方案： 恢复 YUV_Reprocess ISP 开关、 效果 ISP 调整， 复测 PASS。

复盘：

第二轮挂测使用 1030 daily 软件，场景 3 FAIL 是 FOV 问题导致的： Unable to find chart in scene!

分析过程中，使用的 10.31 之后的软件复测，所以解决完 FOV 问题之后，就出现了场景 3 EE 的问题。 其实此时就已经有前、后摄本测试项、前摄 scene1_2#test_reprocess_noise_reduction 的问题了。 这些问题就是由于 10.31 入库的 yuv-reproc bypass ISP 效果参数修改 导致的。

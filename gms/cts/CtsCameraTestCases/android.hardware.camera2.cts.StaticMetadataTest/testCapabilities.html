testCapabilities

测试项描述

预检查项

无。

测试内容与目标

针对安卓定义的 CameraMetadata.REQUEST_AVAILABLE_CAPABILITIES_* 做相应 CaptureRequest, CaptureResult, CameraCharacteristics 等特性支持的检查。

[孙海鑫 记录于 2023.01.13]

历史问题

项目

BE8

解决者

sunhaixin

备注

孙海鑫 记录于 2023.01.13

异常描述

异常原因

缺失相关 capability 的配置

解决方案

 
CONFIG_ENTRY_VALUE(MTK_REQUEST_AVAILABLE_CAPABILITIES_MANUAL_SENSOR, MUINT8)
CONFIG_ENTRY_VALUE(MTK_REQUEST_AVAILABLE_CAPABILITIES_MANUAL_POST_PROCESSING, MUINT8)

关联Case

更多信息

项目

P671L

解决者

zhoushidan

备注

P671LP672L-3572 [ArCore] 孙海鑫 记录于 2024.05.16

异常描述

 
java.lang.Throwable(Test failed for camera 1: Camera 1 doesn't list capability
REQUEST_AVAILABLE_CAPABILITIES_MANUAL_SENSOR but meets all requirements)
java.lang.Throwable(Test failed for camera 1: Camera 1 doesn't list capability
REQUEST_AVAILABLE_CAPABILITIES_READ_SENSOR_SETTINGS but meets all requirements)

异常原因

前摄支持 MANUAL_SENSOR 和 READ_SENSOR_SETTINGS 却没有配置对应 capability。

解决方案

vendor/sprd/modules/libcamera/hal3_2v7/SprdCamera3Setting.cpp

if (cameraId < 1) { // 此处有tran注释，猜测此处原本为 cameraId < 2，未区分前后摄
    memcpy(s_setting[cameraId].requestInfo.available_capabilities,
           kavailable_capabilities,
           sizeof(kavailable_capabilities) - sizeof(uint8_t));
} else {
    memcpy(s_setting[cameraId].requestInfo.available_capabilities,
           kavailable_capabilities_without_high_speed_video,
           sizeof(kavailable_capabilities_without_high_speed_video) - sizeof(uint8_t));
}
if (mMacroManualSensor) { // 此处追加 capabilities
    if (cameraId < 1) {
        memcpy(s_setting[cameraId].requestInfo.available_capabilities +
               sizeof(kavailable_capabilities) - sizeof(uint8_t),
               kavailable_manual_capabilities, sizeof(kavailable_manual_capabilities));
    } else {
        memcpy(s_setting[cameraId].requestInfo.available_capabilities +
               sizeof(kavailable_capabilities_without_high_speed_video) - sizeof(uint8_t),
               kavailable_manual_capabilities, sizeof(kavailable_manual_capabilities));
    }
}

关联Case

com.google.ar.infrastructure.compliance.sft.androiddatasource.AndroidDataSourceTest#testCameraRollingShutterTime

更多信息

展锐的 board.json 及其 ConfigureMgr 对 MANUAL_SENSOR 的控制粒度太大，不同功能耦合严重； 此外展锐的代码设计不合理，容易踩坑。

相关 capability 数组定义：

const uint8_t kavailable_capabilities[] = {
    ANDROID_REQUEST_AVAILABLE_CAPABILITIES_BACKWARD_COMPATIBLE,
    ANDROID_REQUEST_AVAILABLE_CAPABILITIES_BURST_CAPTURE,
    ANDROID_REQUEST_AVAILABLE_CAPABILITIES_CONSTRAINED_HIGH_SPEED_VIDEO,
    ANDROID_REQUEST_AVAILABLE_CAPABILITIES_MONOCHROME  //因"- sizeof(uint8_t)"被剔除
};
const uint8_t kavailable_capabilities_without_high_speed_video[] = {
    ANDROID_REQUEST_AVAILABLE_CAPABILITIES_BACKWARD_COMPATIBLE,
    ANDROID_REQUEST_AVAILABLE_CAPABILITIES_BURST_CAPTURE,
    ANDROID_REQUEST_AVAILABLE_CAPABILITIES_MONOCHROME
};
const uint8_t kavailable_manual_capabilities[] = {
    ANDROID_REQUEST_AVAILABLE_CAPABILITIES_MANUAL_SENSOR,
    ANDROID_REQUEST_AVAILABLE_CAPABILITIES_READ_SENSOR_SETTINGS
};

日志中标红的 “0” 导致后续追加的 capabilities 无法被读取，所以前摄只有 BACKWARD_COMPATIBLE 和 BURST_CAPTURE。 展锐设计的 capabilities 容量只有 6。

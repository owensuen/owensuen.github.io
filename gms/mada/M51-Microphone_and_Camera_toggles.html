GMS规范测试：M51 - Microphone and Camera toggles

GMS Requirement ID

GMS-8.28-001 (/gms/policies/domains/user-experience#GMS-8.28-001)

Prerequisites

  • Applicable on DEVICEs running Android 12 or higher

  • Handheld device implementations declare android.hardware.microphone and/or declare android.hardware.camera.any

  • Execute below test if android.hardware.SensorPrivacyManager.supportsSensorToggle(int) is TRUE

  • Run CtsSensorPrivacyTestCases in cts, if mic tests are skipped then their device does’ t support mic toggle, if cam tests are skipped then their device doesn’t support cam toggle. Alternatively, a partner may write an app to call the mentioned API

Test Instructions

  1. Check if toggles for mic and camera are in Privacy Settings page and that the string clearly communicates that disabling the toggles will block access to mic and camera

  2. Disable the microphone toggle, launch apps that need access to microphone (e.g., Recorder, Assistant, Camera recorder) and verify that the app does not receive audio stream

  3. Repeat step #2 for camera and launch apps that need access to camera (e.g., camera, Duo, Meet) and verify that the app does not receive camera stream (screen should be black)

  4. If both Mic/Camera in one then use the default camera app to record a video and verify the playback

Passing Requirement Example

CDD Description

Android CDD 9.8.13. SensorPrivacyManager : If device implementations provide the user a software affordance to turn off the camera and/or microphone input for the device implementation, they:

  • [C-1-1] MUST accurately return ‘true’ for the relevant supportsSensorToggle() API method.

  • [C-1-2] MUST, when an app tries to access a blocked microphone or camera, present the user with a non-dismissable user affordance that clearly indicates that the sensor is blocked and requires a choice to continue blocking or unblock as per the AOSP implementation which meets this requirement.

  • [C-1-3] MUST only pass blank (or fake) camera and audio data to apps and not report an error code due to the user not turning on the camera nor microphone via the user affordance presented per [C-1-2] above.

异常描述

Settings – Privacy – 只关闭 Camera Access 权限，相机录制视频无声音

异常原因

未知

解决方案

frameworks/base/core/res/res/values/config.xml

<bool name="config_supportsCamToggle">false</bool>

该值配置为 false 以禁止启用摄像头切换开关功能，并且 SensorPrivacyCameraTest 下的所有测试项都会 ASSUMPTION_FAILURE。

关联Case

android.sensorprivacy.cts.SensorPrivacyCameraTest 下的所有 Case

自Android12开始的新特性“麦克风和摄像头切换开关”：

参考 行为变更：所有应用#麦克风和摄像头切换开关 以及 解释对比较敏感信息的访问权限#切换开关

项目

KL5(N)

解决者

sunhaixin

备注

Gerrit:1051322 孙海鑫 记录于 2024.10.11

异常描述

【GMS规范】隐私权限关闭“摄像头访问权限”，打开相机，隐私权限弹窗点击取消解锁摄像头，快速切换模式，切换模式后出现实时预览画面，不符合GMS规范

异常原因

1、hi5022q 驱动 通过 写0x0B04寄存器实现 set_test_pattern_mode；

2、hi5022q 驱动 sensor_init 时候会将 0x0B04寄存器 复位至正常预览出帧的值；

3、问题手法下: (1 ) 点击取消后，打开相机，FWK、HAL 一直下发 SENSOR_TEST_PATTERN_MODE_BLACK(5)，预览全黑，正常； (2 ) 快速切换模式时，无隐私权限弹窗，AAASensorMgr 没有销毁重建（uninit、init），导致其内部记录的 m_i4TestPatternMode 值未复位为0；

4、综上，切换模式后，FWK、HAL 一直下发 5，但驱动 test_pattern_mode 实际已被复位，而 AAASensorMgr 因为没有检测到 m_i4TestPatternMode 值的变化而没有调用驱动 set_test_pattern_mode

解决方案

对比 S666LN 项目（同后摄hi5022q）无此问题，参考 hal3a v3.0，在 v1.0 的 Hal3AAdapter3 在config 阶段将 mParams.i4SensorTestPattenMode 复位为 0。 快速切换模式重新配流后，i4SensorTestPattenMode复位后又被设置为 5 ，产生变化，AAASensorMgr 调用驱动设置 test_pattern_mode。

关联Case

更多信息

set_test_pattern_mode 调用链： Hal3AAdapter3::config 或者 Hal3AAdapter3::setNormal -> Hal3ARawImp::setParams -> AAASensorMgr::enableSensorTestPattern -> 调用驱动 set_test_pattern_mode

KM5TOS1510-1297 孙海鑫 记录于 2025.03.12

异常描述

禁用相机权限，进入相机点击取消后仍可使用相机功能（现象同 KL5(N) 项目 bug 记录 ）

【GMS规范】隐私权限关闭“摄像头访问权限”，打开相机，隐私权限弹窗点击取消解锁摄像头，快速切换模式，切换模式后出现实时预览画面，不符合GMS规范

异常原因

1、test_pattern_mode 复位而未调用驱动的问题原因同 KL5(N) 项目 bug 记录；

2、MTK_SENSOR_AVAILABLE_TEST_PATTERN_MODES 配置不受驱动支持。

解决方案

1、在 v1.0 的 Hal3AAdapter3 在 config 阶段将 mParams.i4SensorTestPattenMode 复位为 0（同 KL5(N) 项目 bug 记录）；

2、MTK_SENSOR_AVAILABLE_TEST_PATTERN_MODES 配置由 [0 1] 改为 [0 5]。

（0：OFF，1：SOLID_COLOR，5：BLACK）
